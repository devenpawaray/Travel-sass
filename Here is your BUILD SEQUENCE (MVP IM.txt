# 🧩 PHASE 3 — EVENT SYSTEM (CORE ENGINE)

## 🎯 Goal:

Everything becomes traceable events.

---

## 3.1 Create event logger function

```ts
createEvent({
  tenant_id,
  event_type,
  payload
})
```

---

## 3.2 Every mutation MUST call:

* event insert
* audit log (if financial or state change)

---

## 3.3 Standard events to implement:

* RAW_IMPORT_CREATED
* IMPORT_APPROVED
* INVENTORY_CREATED
* QUOTE_CREATED
* QUOTE_LOCKED
* BOOKING_CONFIRMED
* KILL_SWITCH_TRIGGERED

---

## 🧠 RULE:

No DB update without event log.

---

# 🧠 PHASE 4 — STATE MACHINE ENGINE (BOOKING FLOW)

## 🎯 Goal:

Prevent illegal transitions.

---

## 4.1 Define allowed transitions:

```text
QUOTE_CREATED
→ PRICE_LOCKED
→ PAYMENT_PENDING
→ PAYMENT_VERIFIED
→ BOOKING_CONFIRMED
```

---

## 4.2 Build validator:

```ts
validateStateTransition(current, next)
```

Reject invalid transitions.

---

## 4.3 Enforce at API level

Every booking update must:

* check current state
* validate transition
* emit event
* update DB

---

# 📥 PHASE 5 — IMPORT SYSTEM (RAW DATA → STRUCTURED DATA)

## 🎯 Goal:

Simulate AI ingestion pipeline.

---

## 5.1 Create API:

`POST /api/import`

Input:

* raw travel data (mock allowed)

---

## 5.2 Processing flow:

1. store in `raw_imports`
2. simulate AI parsing → parsed_json
3. set status = pending
4. send to approvals_queue

---

## 🧠 RULE:

Nothing enters inventory without approval.

---

# 🧑‍💼 PHASE 6 — APPROVAL SYSTEM (SECRETARY GATE)

## 🎯 Goal:

Human validation layer before system truth.

---

## 6.1 API endpoints:

* GET /approvals
* POST /approve
* POST /reject

---

## 6.2 On APPROVE:

* move data → inventory_master
* emit event: IMPORT_APPROVED
* create versioned inventory record

---

## 🧠 RULE:

Approval = system truth creation moment.

---

# 🧾 PHASE 7 — INVENTORY SYSTEM

## 🎯 Goal:

Create usable travel inventory.

---

## 7.1 Inventory structure:

* service type
* partner
* price
* status (draft/active/locked)
* version

---

## 7.2 Rules:

* only approved imports can create inventory
* inventory is versioned (never overwritten)

---

# 💰 PHASE 8 — PRICING ENGINE (RULE SYSTEM)

## 🎯 Goal:

Enforce profit safety before quotes.

---

## 8.1 Implement rules:

* Commission 2 rules (from system_config)
* partner risk rules
* margin threshold rules

---

## 8.2 Quote generation flow:

1. consultant selects inventory
2. system applies rules
3. if valid → create quote
4. else → block or require admin approval

---

## 🧠 RULE:

No quote bypasses rules engine.

---

# 📦 PHASE 9 — QUOTE SYSTEM

## 🎯 Goal:

Controlled pricing output system.

---

## 9.1 API:

`POST /quote`

Inputs:

* inventory_id
* client data

---

## 9.2 Output:

* price
* margin
* status
* locked/unlocked

---

## 9.3 Event:

QUOTE_CREATED must always fire

---

# 🧾 PHASE 10 — BOOKING SYSTEM

## 🎯 Goal:

Finalize transactions safely.

---

## 10.1 Flow:

Quote → Booking → Payment → Confirmation

---

## 10.2 Rules:

* only locked quotes can be booked
* booking triggers state machine
* confirmation triggers audit snapshot

---
